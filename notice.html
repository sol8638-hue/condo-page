Ⅰ. 어떻게 만들었나

1. 제작 방식 — AI 코딩 에이전트 활용

AI 코딩 에이전트(Claude Code)와 대화하는 방식으로 제작.

  • 자연어로 요구사항 전달 → AI가 코드 작성·수정을 반복하며 기능 완성. (예: "신청자가 취소 요청을 할 수 있게 해줘" → AI가 화면·데이터베이스·메일까지 구현)
  • 화면 디자인은 AI 디자인 도구(클로드 디자인)로 시안을 만든 뒤 반영.

2. 사용 기술

3. 설계상의 특징

  • 클라우드 기반 : 담당자 PC 상태와 무관하게 신청·문의·메일이 24시간 작동.
  • 개인정보 보호 : 신청·문의는 본인(사번+휴대폰 뒷 4자리)만, 관리 기능은 담당자(비밀번호)만 접근하도록 서버 단에서 통제.
  • 민감정보 보호 : 한화 로그인 정보·DB 접근 키·메일 발송 비밀번호 등은 코드에 직접 넣지 않고 환경변수(.env, 외부 비공개)로 분리 관리해 유출을 방지. 공개 페이지에는 공개용 키만 사용.
  • 메일 발송 방식 : 회사 메일 서버는 사내망 전용이라 클라우드에서 연결 불가 → 외부 발송이 가능하고 회사 메일함까지 정상 도착하는 인사팀 지메일을 발송 통로로 사용. (받는 주소는 회사 이메일 사번@okfngroup.com 동일)

4. 한계점 — 실시간 객실 현황은 담당자 PC가 켜져 있어야 함

  • 신청·문의·메일 등 대부분 기능은 클라우드로 옮겨 PC 없이도 24시간 작동함. 다만 잔여객실 현황 수집만은 담당자 PC에서 이루어짐.
  • 이유 : 한화리조트 예약 사이트는 회원 로그인을 해야만 잔여객실을 조회할 수 있음. 이 로그인·조회를 자동으로 하려면 실제 브라우저를 띄워 한화 사이트에 로그인해야 하는데, 그 자동화 프로그램이 담당자 PC에 설치되어 작업 스케줄러로 30분마다 실행됨.
  • 한화 사이트는 외부 서버의 자동 접근을 제한하고 로그인 세션·추가 인증을 요구할 수 있어, 클라우드(외부 서버)에서 안정적으로 돌리기 어려움. 그래서 실제 사용 중인 PC의 브라우저로 로그인하는 방식이 가장 안정적임. → 이 부분만 PC에 의존.
  • 또한 클라우드에서 브라우저 자동화를 24시간 돌리려면 항상 켜진 유료 서버가 추가로 필요함. 현재는 신청·문의·메일·호스팅을 모두 무료 요금제로 운영 중이라, 잔여객실 수집만 담당자 PC로 처리해 추가 비용 없이 운영함.
  • 따라서 그 PC가 꺼져 있으면 새 잔여객실 정보가 수집되지 않고 마지막 수집 값에서 멈춤. (이미 수집된 값은 계속 표시되며, 페이지·신청·문의·메일은 클라우드라 정상 작동.)
  • PC를 다시 켜면 자동으로 수집이 재개되어 최신화됨.
