한화리조트 콘도 예약 시스템 — 제작 방법 및 테스트 안내

Ⅰ. 어떻게 만들었나

1. 제작 방식 — AI 코딩 에이전트 활용

AI 코딩 에이전트(Claude Code)와 대화하는 방식으로 제작.

  • 자연어로 요구사항 전달 → AI가 코드 작성·수정을 반복하며 기능 완성. (예: "신청자가 취소 요청을 할 수 있게 해줘" → AI가 화면·데이터베이스·메일까지 구현)
  • 화면 디자인은 AI 디자인 도구(클로드 디자인)로 시안을 만든 뒤 반영.

2. 사용 기술

  • 화면(프론트엔드) : HTML · CSS · JavaScript — 프레임워크 없이 단일 페이지로 가볍게 구성
  • 빌드 : Node.js 스크립트 — 데이터와 화면 틀을 합쳐 최종 페이지를 자동 생성
  • 호스팅 : Cloudflare Pages — 항상 접속 가능한 웹 주소 제공, 코드 변경 시 자동 배포
  • 데이터베이스·백엔드 : Supabase (PostgreSQL) — 신청·문의·메일 데이터 저장 및 보안 처리
  • 잔여객실 수집 : Playwright + 작업 스케줄러 — 한화리조트 사이트에서 30분마다 자동 수집
  • 메일 발송 : Supabase Edge Function + 지메일 — PC 없이 24시간 자동 발송
  • 버전 관리 : Git · GitHub — 코드 이력 관리

3. 설계상의 특징

  • 클라우드 기반 : 담당자 PC 상태와 무관하게 신청·문의·메일이 24시간 작동.
  • 개인정보 보호 : 신청·문의는 본인(사번 + 휴대폰 뒷 4자리)만, 관리 기능은 담당자(비밀번호)만 접근하도록 서버 단에서 통제.
  • 메일 발송 방식 : 회사 메일 서버는 사내망에서만 접속되어 클라우드에서 연결할 수 없으므로, 외부 발송이 가능하고 회사 메일함까지 정상 도착하는 인사팀 지메일 계정을 발송 통로로 사용. (받는 주소는 회사 이메일 사번@okfngroup.com 동일)

4. 한계점 — 실시간 객실 현황은 담당자 PC가 켜져 있어야 함

  • 잔여객실 현황은 담당자 PC에서 한화리조트 사이트에 자동 로그인해 30분마다 수집. 한화 사이트 로그인·조회를 브라우저로 자동 수행해야 하므로, 이 작업이 도는 PC가 켜져 있어야 함.
  • PC가 꺼져 있으면 새로운 잔여객실 정보가 갱신되지 않고 마지막 수집 시점 값에서 멈춤. (페이지·신청·문의·메일은 클라우드에서 동작하므로 정상 작동.)
  • PC를 다시 켜면 자동으로 최신화 재개.

Ⅱ. 사전 테스트 안내

1. 개요

  • 접속 주소 : https://okfg-condo.pages.dev/ (PC·모바일 모두 가능, 설치 불필요)
  • 테스트 기간 : 2026.07.10 ~ 2026.07.15

2. 주요 기능

직원용 — 요금표·객실 사진 조회, 예약 달력(잔여객실 현황), 예약 신청 및 조회, 취소 요청, 1:1 문의

관리자용(담당자 전용) — 현황 대시보드, 상태 관리, 안내·답변 메일 발송, 신규 접수 자동 알림, 발송 내역 조회, 엑셀 다운로드

3. 관리자 화면 접속 방법

  • 1. 페이지 맨 아래로 이동
  • 2. 하단의 「인사팀 관리자」 클릭
  • 3. 비밀번호 ★★★★★★ (여기에 비밀번호 입력) → 관리자 대시보드 열림

※ 새로운 신청·문의·답글이 등록되면 담당자 사내메일로 자동 알림이 발송되어, 관리자 화면에 들어가지 않아도 접수 사실을 바로 확인 가능.

4. 테스트 요청 항목

  • 예약 달력·잔여객실·객실 사진이 정상 표시되는지 확인
  • 신청서 제출 후 내 신청 조회로 정상 확인 (잘못된 정보로는 조회되지 않는지도 확인)
  • 신청 건 취소 요청 후 상태 변경 확인
  • 1:1 문의 등록 후 답변·답글이 정상 표시되는지 확인
  • (담당자) 상태 변경 및 메일 발송 → 실제 수신 확인
  • 휴대폰 화면에서 정상 작동 여부 확인
